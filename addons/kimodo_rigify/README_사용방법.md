# Kimodo Local → Rigify / Mixamo 애드온 v0.3.0

Blender의 3D View N 패널에서 두 로컬 Kimodo로 SOMA 모션을 생성하고, 생성된 표준 Rigify 리그의 FK 컨트롤에 자동으로 베이크한다. 추가 모델이나 온라인 생성 서비스를 사용하지 않는다.

## 설치와 실행

설치 ZIP: `dist/kimodo_rigify-0.3.0.zip`

1. Blender `Edit → Preferences → Add-ons` 메뉴의 **Install from Disk**에서 ZIP을 선택하고 `Kimodo Local → Rigify`를 켠다.
2. 애드온 환경 설정의 **로컬 설치 상위 폴더**는 기본값 `<저장소>/runtime`를 사용한다. 그 아래 기존 `Kimodo`, `KimodoCpp` 설치를 읽는다.
3. Rigify의 **Generate Rig**로 만들어진 Armature를 준비한다. metarig 자체는 리타게팅 대상이 아니다.
4. 3D View에서 `N`을 눌러 **Kimodo** 탭을 연다. **대상 리그 (Rigify / Mixamo)**에 생성된 리그를 지정한다.
5. 생성 엔진, 영어 동작 설명, 프레임 수, 단계 수, 시드를 지정하고 **모션 생성**을 누른다. 기본값은 C++ / 90프레임 / 100단계 / 시드42이다.
6. 생성 완료 후 SOMA 소스를 가져오고, **생성 후 자동 리타게팅**이 켜져 있으면 Rigify FK Action을 만든다. 타임라인에서 재생한다.

Blender의 Python에는 PyTorch를 설치하지 않는다. 외부 설치의 실행 파일로 생성하고 Blender에는 결과만 가져온다. 생성은 비동기이며 **생성 취소** 또는 Esc로 이 애드온이 시작한 작업만 중단한다. 가져오기/베이크 단계에는 잠시 시간이 걸릴 수 있다.

## 엔진 차이

| 엔진 | 출력 및 베이크 | 실행 방식 |
|---|---|---|
| 공식 Kimodo | SOMA 77관절 BVH, 표준 Rigify에서 54개 컨트롤 매핑 | CPU Llama + CUDA 모션 |
| Kimodo.cpp | SOMA 30관절, 표준 Rigify에서 몸통/팔/다리 24개 컨트롤 매핑 | Vulkan + Q8, 레이어 청크8 |

모션 모델은 두 설치 모두 **SOMA-RP v1.1**만 사용한다. 실행 중 모델을 추가로 다운로드하지 않는다. 공식 엔진은 문장이 여러 개여도 지정한 프레임 수의 하나의 모션으로 처리한다.

공식 엔진은 Llama 로딩 때문에 메모리를 많이 사용한다. 공식 웹데모(7860)와 함께 실행하면 인코더가 중복 로드된다. 생성 전에 기존 `Kimodo/08_Stop_Demo.bat`으로 공식 웹데모를 종료하는 것을 권장한다. 메모리가 부족하면 애드온은 실행 전에 안내하고 멈춘다. C++의 웹데모에서 생성 중인 작업도 끝낸 후 애드온을 사용한다.

## 기존 모션과 복원

- **기존 BVH / GLB 가져오기**: 공식 SOMA BVH 또는 Kimodo.cpp SOMA 30관절 노드 GLB를 가져온다. GLB는 30fps 결과를 지원한다. 일반 캐릭터 GLB는 Blender의 기본 가져오기를 사용한다.
- **Rigify 자동 리타게팅 / 베이크**: 패널에 지정한 소스 SOMA에서 대상 Rigify로 다시 베이크한다.
- **루트 이동 포함**: 시작 프레임 위치를 기준으로 이동을 전달하고 다리 길이 비율로 크기를 맞춘다. 끄면 이동을 제자리로 만든다.
- **이전 Action / 리그 상태 복원**: 직전 Action, NLA 사용 여부, IK/FK 속성 및 포즈를 되돌린다. 이전 Action은 삭제하지 않고 보존한다.
- 새 베이크는 NLA와 혼합되지 않도록 대상의 NLA 평가를 꺼 둔다. NLA 트랙 자체는 보존하며 복원 버튼이 이전 사용 여부를 되돌린다.
- 출력과 로그: `KimodoBlender/outputs/<시간-작업ID>/`. 오류가 나면 **생성 로그 열기**로 확인한다.

## 1~90 뒤에 91~180 이어 붙이기

1. 대상 Rigify를 지정하고 시작 프레임1, 90프레임으로 첫 모션을 생성한다. **기존 모션에 이어 붙이기**는 꺼 둔다.
2. **다음 구간 (기존 모션 뒤에 추가)**을 누르면 시작 프레임이91로 바뀌고 이어 붙이기가 켜진다.
3. 두 번째 프롬프트를 입력하고 90프레임으로 생성한다. 기존 BVH를 가져오는 경우에도 같은 설정을 사용한다.
4. 앞 Action의 키를 복사한 새 Action에91~180을 추가한다. 타임라인은1~180이 되며 첫90프레임은 보존한다. 이전 Action과 NLA 트랙은 삭제하지 않는다.
5. 세 번째 구간은 다시 **다음 구간**을 눌러181부터 생성한다. 겹치거나 빈 구간이 생기는 시작 프레임은 실행 전에 거부한다.

새 구간의 루트 이동은 이전 구간의 마지막 위치에서 시작한다. 자세의 자동 블렌딩 및 진행 방향 회전 정렬은 포함하지 않으므로90→91에서 자세가 바뀔 수 있다. 엔진 선택과 대상 리그는 독립적이며 완료 상태에 대상 이름과 전체 프레임 범위를 표시한다. 이전 상태 복원은 Action과 함께 이전 타임라인 범위도 복원한다.

`dist/Kimodo_경계에서공격_1-180.blend`는 공식 엔진의 실제 출력으로 경계 자세1~90, 오른팔 공격91~180을 이어 붙인 검증 파일이다. `logs/sequence_verified.json`에 첫 구간 키 보존, 기존 포즈 오차0, 경계 루트 위치 오차0, 두 번째 소스의 대표 팔·다리 방향 오차0, 중복 구간 거부, 이전90프레임 복원 검사 결과를 기록했다.

## 확인용 파일

- `dist/Kimodo_Rigify_검증.blend`: 공식/C++ 걷기를 나란히 베이크한 Rigify 리그 두 개와 뼈를 따라 움직이는 간단한 표시용 메시. 30fps / 1–90프레임으로 재생한다. 소스 Armature는 숨겨 두었다.
- `dist/rigify_preview.png`: 30프레임의 시각 검증 이미지.
- `logs/backends_verified.json`: 두 실제 엔진 생성 검사.
- `logs/blender_verified.json`: BVH/GLB 가져오기, 대표 팔/다리 방향, 루트 이동 검사.
- `logs/modal_verified.json`: 실제 생성 연산자 → 가져오기 → 자동 베이크 검사.
- `logs/restore_verified.json`: 이전 Action·NLA·IK/FK 복원 검사.

## 지원 범위와 검증

Windows / Blender **5.2.2 LTS** / 기본 Human Rigify 생성 리그로 검증했다. `root`, `torso`, `hips`, `chest`, `upper_arm_fk.*`, `thigh_fk.*` 등의 표준 컨트롤 이름을 사용한다. 이름을 바꾼 커스텀 리그와 비인간 골격, 링크된 읽기 전용 리그는 이 버전의 자동 매핑 대상이 아니다. 균일한 양수 스케일을 사용한다.

2026-10-04, 애드온 실행 코드로 90프레임/100단계 걷기를 두 엔진에서 생성했다. 측정한 생성 시간은 C++ 약21초, 공식 약55초이며 모델 로딩을 포함한다. 생성 연산자의 60프레임 테스트에서 가져오기와 24개 FK 컨트롤 자동 베이크까지 완료했다. 90프레임 소스의 대표 팔/다리 4개를 1/30/60/90프레임에서 검사했고, 방향 오차 3도 미만·루트 이동 오차 0.0001m 미만 기준을 통과했다. GLB와 원시 모션의 변환 결과도 일치했다.

이것은 FK 자동 리타게팅이다. 발의 지면 고정이나 손의 무기 접촉을 새로 계산하는 IK 보정기는 포함하지 않는다. 체형·자세가 크게 다른 캐릭터에서는 발·손 접촉과 몸통을 보정해야 할 수 있다. 얼굴 표정은 전달하지 않으며 C++ 출력에는 세부 손가락 동작이 없다. 실제 게임용 캐릭터 스킨에 대한 검증은 별도 단계다.

## 소스와 라이선스

애드온의 SOMA 30관절 정의는 NVIDIA Kimodo의 Apache-2.0 골격 정보를 사용하는 kimodo.cpp에서 가져왔다. `kimodo_rigify/NOTICE.txt`와 `LICENSE`를 포함했다. 모션 모델과 Llama의 사용 조건은 각 원본 모델 라이선스를 따른다. ZIP에는 모델 가중치·인증 정보가 포함되지 않는다.

공식 소스: https://github.com/nv-tlabs/kimodo

## Mixamo 지원 (v0.3.0, 2026-10-05)

Blender 5.2 설치본에 업데이트를 적용했다. 열려 있는 Blender는 파일을 저장하고 재시작해야 새 코드가 로드된다. 다른 Blender 설치에는 dist/kimodo_rigify-0.3.0.zip을 설치한다.

1. Mixamo 오토리깅 FBX를 Blender에 가져온다.
2. Kimodo 탭의 대상 리그 (Rigify / Mixamo)에 Mixamo Armature를 지정한다. 메시 오브젝트를 선택하지 않는다.
3. 감지된 리그: MIXAMO를 확인한다.
4. 생성 후 자동 리타게팅을 켜고 모션을 생성하거나 기존 SOMA BVH/GLB를 가져온다.

mixamorig:Hips, mixamorigHips, Hips 형태 및 다른 콜론 네임스페이스를 지원한다. 리그나 웨이트의 이름을 변경할 필요 없다. Mixamo의 LeftUpLeg/LeftLeg를 SOMA의 LeftLeg/LeftShin에 대응한다. Hips 본에 루트 이동을 기록한다. 기존 Action/NLA 상태를 보존하고 이어 붙이기 및 복원을 지원한다.

Rigify는 기존 FK 컨트롤 매핑을 유지한다. metarig는 여전히 대상이 아니다. 지원 형식이 아닌 사용자 정의 리그는 자동 추측하지 않고 필수 본 누락을 표시한다. 양수 균일 오브젝트 스케일이 필요하다.

검증: Downloads/player-mixamo.fbx로 SOMA30(22본) 및 SOMA77(52본) 적용, 팔·다리 방향, FBX 스케일/오브젝트 회전, 루트 이동/제자리, 이어 붙이기/복원, 본 계층 및 웨이트 보존을 검사했다. 현재 열려 있는 사용자의 아바타 파일을 수정한 테스트는 아니다. 검증 씬은 dist/Kimodo_Mixamo_verified.blend, 기록은 logs/mixamo_verified.json에 있다. 기존 Rigify 두 엔진 90프레임 검사도 통과했다.

발 접지, 관절 변형, 손가락과 무기 파지는 아바타의 비율 및 웨이트에 따라 최종 검토가 필요하다. 생성된 애니메이션이 메쉬 웨이트 오류까지 자동 보수하지 않는다.
